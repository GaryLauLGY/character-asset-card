# 通用制作与拼合示例

以下是规划示例，不是已生成的角色资料，也不依赖作者的个人项目路径。

## 简单版：四张独立图

| 文件 | 构图 | 参考分工 |
|---|---|---|
| `01_脸部特写.png` | 正面脸部，足够的五官展示面积 | 身份图负责面部；造型图负责发型与眼镜等指定属性 |
| `02_正面.png` | 用户指定的全身或膝上，统一站姿 | 同一身份与服装约束 |
| `03_侧面.png` | 明确人物哪侧靠近相机，统一景别 | 同一身份与服装约束，写清鼻尖方向 |
| `04_背面.png` | 与正面相同景别与服装 | 看不到的背面结构标为设计补全 |

四张分别生成、分别检查，然后通常按2×2拼合。不同尺寸先调整留白或扩大画布，不缩放原图。最终文件夹保留完整卡PNG与这四张采用原图。

## 复杂版：由用途决定模块

例如角色展示可选择正面、侧面、背面、平静表情、微笑表情、服装材质和鞋履细节；用户需要包袋再增加相应模块。数量不是固定九格。每个模块独立生成，服装细节以实际采用人物图的穿着为依据，避免鞋、扣件、肩带方向不一致。

身份参考与造型参考可以是不同图片，但要把每个属性的职责写清楚。纯鞋履或包袋图无需机械附上人脸参考。

## HTML与原像素导出

HTML/CSS可以用于排版预览、文字和色板。响应式页面缩小显示只影响观看大小，不能据此声称导出保留原像素。

导出时可先制作文字与留白底图，再用Canvas或Pillow把采用原图按自然尺寸、整数坐标放入。模块不得缩放、裁切或调色；导出PNG后逐模块比较解码像素。模型生成图本身的清晰度与相似度仍需观察，拼合校验只证明排版没有改变原图像素。

下面的映射是假设单张源图为1024×1536的示例；实际使用时填写真正的尺寸与坐标。源路径相对于映射JSON所在目录。

```json
[
  {"id": "front", "source": "02_正面.png", "x": 40, "y": 120, "width": 1024, "height": 1536},
  {"id": "side", "source": "03_侧面.png", "x": 1104, "y": 120, "width": 1024, "height": 1536}
]
```

运行随技能提供的脚本（Python需要Pillow）：

```bash
python3 scripts/verify_native_pixels.py 完整资产卡.png 像素区域映射.json --report 像素校验结果.json
```

脚本验证最终文件是PNG、区域为整数且不越界、尺寸相同以及RGBA各通道像素完全一致。所有模块一致返回0，像素不一致返回1；输入错误或报告文件已存在会拒绝执行。报告只验证映射中列出的模块，所以映射必须覆盖全部采用图片。它不会生成图片、排版或自动验收身份。
