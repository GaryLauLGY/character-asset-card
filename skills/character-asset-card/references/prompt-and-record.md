# 模块提示词与记录

这些是可替换的组织模板，不是工具固定字段，也不是H3视频模板。以当前生图工具支持的参考方式执行；声明“新生图”不能把实际编辑调用变成生图。

## 单次请求只保留当前视角

先在项目记录列清角色设定、所有模块和补全依据。给生图工具的提示词只保留本格可见内容、参考职责和一个朝向；不是把整份制作说明发给模型。“一张图片”不足以约束主体数量，每个请求必须以“只有一名人物、主体只出现一次、一个固定视角”开头。

六宫格使用 [prepare_six_grid_request.py](../scripts/prepare_six_grid_request.py) 组装单次请求。输入JSON只填本图可见的身份／服装／背景和原始参考，准备器加入当前视角、取景及对应白模。以下是**纯背面身体**的一次输入示例，不能把其他模块说明拼入：

```json
{
  "prompt": "生成全新真实摄影图。图1仅负责本人可见肤色、手部、自然体态和服装。本人身材自然，深蓝西装外套、浅蓝衬衫、同色直筒西裤、黑皮鞋；衣服后背中缝自然。中性灰背景与柔和棚光，无文字。",
  "referenced_image_paths": ["/path/to/原始参考照.png"],
  "transparent_background": false
}
```

```bash
python3 scripts/prepare_six_grid_request.py 本格设定.json --view body-back --output 实际生图参数.json
python3 scripts/check_framing_reference.py 实际生图参数.json --view body-back
```

实际调用使用准备器输出的同一份 `prompt` 和图片参数，检查后不再重写或加回制作备注。准备器只准备JSON，不调用生图，也不覆盖已有输出。`--view` 每次只选一个：`head-front`、`head-left`、`head-back`、`body-front`、`body-left` 或 `body-back`；命令行选择值不是生图工具参数。自定义构图时，准备和检查两步都传同一个 `--framing-reference`，不覆盖用户已指定的取景。

生成前检查会要求本视角的单主体开头，拒绝“正背面”、多个视角并列的正向要求、整卡布局和 `补全：`／`制作记录：` 等备注。背视图统一写“纯背面”“相机在人物正后方”“人物背向相机”。明确的禁止拼贴、禁止第二主体等约束可保留。脚本覆盖已知歧义，不是完整语义解析器，也不能验证实际输出；仍需AI检查画面只出现一个主体、一个朝向。

头部格填写本人面部与发型特征；身体格只写可见体型、肤色、手部和服装，不描述画外五官／表情。原始照片仍负责身份与造型；白模只管相机与边界，不是另一个需要出现在画面里的人物。不要照搬其他角色属性；有多张身份／服装照时，按实际图片编号写清职责。新加入白模在末尾，原参考编号保持。

构图细节见 [six-grid-template.md](six-grid-template.md)。姓名、来源说明、补全部位与依据、模块清单、上下排安排、其他视角、后续拼合要求全部留在制作记录。生成时将已选定的补全结果直接写为本图的可见服装／鞋履，不再携带补全过程或多个候选。

## 各模块变量

- **正面/侧面/背面**：身体与头部是否同向、严格侧面还是3/4、人物哪侧靠近相机、鼻尖朝画面哪边、相同取景上下界，六宫格按上排头部肩颈/下排保留脖子至鞋底分别写取景；指定四视图的正侧背为完整头顶至鞋底并留白。纯侧面时整个人转满90度，头、颈、肩线、胸、髋与脚同向，近侧肩膀遮住远侧肩膀；紧凑头部特写的画外身体也保持此方向。正面人物左侧通常在画面右，背面人物左侧在画面左；姿势变化时重新确认。
- **六宫格构图**：读取 [six-grid-template.md](six-grid-template.md) 的正向取景模板。上下排都保留自然脖子与肩颈连接；下排上边界经过上颈部皮肤，整个下巴／颌线／口鼻／耳朵／后脑都在画外；不能出现封口、空领口或缺失脖子。
- **表情**：平静/轻微闭唇微笑/专注/轻微惊讶等，写出眼、眉、唇的变化程度；头部方向与人脸占比尽量统一。情绪强度按用户需要，不默认夸张大笑。
- **服装**：只展示相关材质、领口、叠穿或扣件结构，写明画面边界，避免无关脸部进入细节格。
- **鞋履**：用已采用人物实际穿着的鞋或用户确认的设计为依据，逐项写鞋帮高度、鞋底轮廓、鞋头、绑带数量/上下顺序、扣件、侧面拼片、配色。指定一只鞋和一个视角；无需附上人脸参考。
- **包袋**：明确是单独物品产品照还是人物身上局部特写，只选一种。只用与物品有关的参考；指定肩带、翻盖/扣件、图案与取景，防止变成人像+包袋双联图。

## 最小留档内容

按当前项目约定记录，Markdown加JSON即可：

- 制作级别（默认六宫格/指定四视图/复杂分模块）、当前角色设定、每张参考职责、用户修正、补全部分、计划模块。六宫格固定上排正侧背头部肩颈近照、下排对应保留脖子的身体六张独立图；四视图模式为头部肩颈近照加正侧背完整全身（用户明确的景别例外需记录）；高清重做记录新生图实际尺寸与旧版对比，不宣称恢复未知细节。
- 每次请求的模块ID/版本、完整提示词、实际工具图片参数及各文件SHA；白模的版本、对应视角、构图职责与提交前检查结果。保存真正使用的参数，不能把计划引用当作实际输入。
- 生成结果文件、实际宽高、SHA、调用标识及耗时（可见时）、是否采用和原因。
- 资产库中该份文件夹的绝对路径、完整卡和全部采用独立图片的逐张清单；页面模块到单份原图的路径/SHA映射、最终PNG中各模块原图的整数像素区域、等宽外框及新增补边量、成品尺寸、逐模块像素一致性校验；HTML只在实际需要时记录。
- 每轮 AI 一致性复检：实际查看的参考与模块版本、问题区域与证据、修复范围、复检结果及未解决项；用户验收单独记录。

局部修正只替换页面中该模块映射；记录前后版本及其他模块SHA不变。若用户要求全部推翻则按新约束整套新建版本，不能将旧图当作全部重新生成的交付。

最终导出不能缩放或裁切模块；上下画框等宽所需补边仅在原图外增加画布，记录原图区域并逐像素核验。卡面默认只留编号与视图短标签，不放标题、版本和参数说明。完整卡与每张采用的模块原图都必须保留，统一放入当前项目约定的 `人物资产卡/<角色与造型>/` 的同一文件夹；每张原图只留一个实体文件，跨版本引用该文件。不要为记录重复复制原图、内嵌大HTML或打包ZIP。去重仅处理已验证的重复副本，不能删除唯一独立原图；按当前版本策略维护现用入口，不复建退役资产兼容链接。历史文件确实缺失时记录实际状态，不能把已缺失路径写成当前可用文件。
