# 模块提示词与记录

这些是可替换的组织模板，不是工具固定字段，也不是H3视频模板。以当前生图工具支持的参考方式执行；声明“新生图”不能把实际编辑调用变成生图。

## 共享角色约束

先用中文列清楚，再按工具需要编写正式提示词。实际提交每个模块时带上相关完整约束，不只写“和上张一样”。

```text
生成一张全新的[摄影/本次指定风格]图像，参考图用于身份与设计参考。
参考A仅负责[面部身份、具体肤色、妆容、瞳色及必须保留的面部特征]。
参考B仅负责[发型、服装层次、版型、图案、配饰]。
本次明确变更：[例如内搭款式；或眼镜去留]。
左右设定：[人物自身哪肩背包、哪腕佩戴何物]。
背景、光线：[统一背景与柔光；肤色保留的具体要求]。
本张模块：[只选一个视角/一种表情/一个细节主体]。
构图：[景别、方向、画幅、完整保留的边界]。
单张连续画面，文字与排版留给后续页面；不生成拼贴或多宫格。
```

不要照搬其他角色的肤色、蓝瞳、长短T或眼镜要求。人物身份与造型照片冲突时，在正式文本中明确每个属性取哪张图，而非泛称“融合两图”。

## 各模块变量

- **正面/侧面/背面**：身体与头部是否同向、严格侧面还是3/4、人物哪侧靠近相机、鼻尖朝画面哪边、相同取景上下界。正面人物左侧通常在画面右，背面人物左侧在画面左；姿势变化时重新确认。
- **表情**：平静/轻微闭唇微笑/专注/轻微惊讶等，写出眼、眉、唇的变化程度；头部方向与人脸占比尽量统一。情绪强度按用户需要，不默认夸张大笑。
- **服装**：只展示相关材质、领口、叠穿或扣件结构，写明画面边界，避免无关脸部进入细节格。
- **鞋履**：用已采用人物实际穿着的鞋或用户确认的设计为依据，逐项写鞋帮高度、鞋底轮廓、鞋头、绑带数量/上下顺序、扣件、侧面拼片、配色。指定一只鞋和一个视角；无需附上人脸参考。
- **包袋**：明确是单独物品产品照还是人物身上局部特写，只选一种。只用与物品有关的参考；指定肩带、翻盖/扣件、图案与取景，防止变成人像+包袋双联图。

## 最小留档内容

无需新建数据库或复杂框架。项目MD加JSON即可：

- 制作级别（简单四视图/复杂分模块）、当前角色设定、每张参考职责、用户修正、补全部分、计划模块。简单版固定脸部、正面、侧面、背面四张独立图；高清重做记录新生图实际尺寸与旧版对比，不宣称恢复未知细节。
- 每次请求的模块ID/版本、完整提示词、实际输入文件及SHA、参考用途、工具实际可见参数。
- 生成结果文件、实际宽高、SHA、调用标识及耗时（可见时）、是否采用和原因。
- 资产库中该份文件夹的绝对路径、完整卡和全部采用独立图片的逐张清单；页面模块到单份原图的路径/SHA映射、最终PNG中各模块的整数像素区域、成品尺寸、逐模块像素一致性校验；HTML只在实际需要时记录。
- 跨模块观察和用户验收分别记录；指出尚未对齐的细节。

局部修正只替换页面中该模块映射；记录前后版本及其他模块SHA不变。若用户要求全部推翻则按新约束整套新建版本，不能将旧图当作全部重新生成的交付。

最终导出不能缩放或裁切模块。完整卡与每张采用的模块原图都必须保留，统一放入根目录 `人物资产卡/<角色与造型>/` 的同一文件夹；每张原图只留一个实体文件，跨版本引用该文件。不要为记录重复复制原图、内嵌大HTML或打包ZIP。去重仅处理已验证的重复副本，不能删除唯一独立原图；按当前项目需要维护引用路径。历史文件确实缺失时记录实际状态，不能把已缺失路径写成当前可用文件。
